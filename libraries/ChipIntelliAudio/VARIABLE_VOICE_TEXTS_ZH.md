# 变量播报预处理文本清单

## 一、核心数字词元

统一使用 ID 300～316 生成下面 17 条短音频，最终 `voice.bin` 必须保持相同编号，
`playVoice("数字字符串")` 才能直接完成自动拼接播放。

| 语音 ID | 文本 | 使用条件 |
| ---: | --- | --- |
| 300 | 零 | 必选 |
| 301 | 一 | 必选 |
| 302 | 二 | 必选 |
| 303 | 三 | 必选 |
| 304 | 四 | 必选 |
| 305 | 五 | 必选 |
| 306 | 六 | 必选 |
| 307 | 七 | 必选 |
| 308 | 八 | 必选 |
| 309 | 九 | 必选 |
| 310 | 十 | 必选 |
| 311 | 百 | 必选 |
| 312 | 千 | 必选 |
| 313 | 万 | 必选 |
| 314 | 亿 | 数值可能达到一亿时需要；建议保留 |
| 315 | 负 | 数值可能为负数时需要；建议保留 |
| 316 | 点 | 需要播报小数时使用；建议保留 |

Arduino 程序中不需要声明这些资源宏。只要最终程序链接了字符串版
`ChipIntelliAudio.playVoice()`，构建后处理就会自动要求 `citool-cli generate`
把完整的 17 条词元加入 TTS 请求。

只播报非负整数且范围小于一亿时，最小集合是前 14 条，即“零～九、十、百、千、万”。
不过资源允许时，建议直接保留完整 17 条，以免后续增加负数或小数后重新制作同一套音色。

## 二、按需增加的数字读法

- `两`：如果产品要求“两百、两千、两万”的口语读法，可单独制作。当前默认算法使用
  正式且通用的“二百、二千、二万”。
- `幺`：电话号码、设备编号、验证码等逐位播报时可代替“一”。这类内容不是普通数值，
  应直接组装 `digits[]` 后调用 `playVoiceSequence()`。
- `正`：只有明确要求读“正五”时才需要；普通正数不播“正”。

年份、版本号、IP 地址、电话号码和验证码通常需要逐位读。例如 2026 年常读作
“二零二六年”，不应使用普通整数算法得到“二千零二十六年”。

## 三、音频制作要求

- 所有词元使用同一发音人、语速、音量、采样率和编码参数。
- 每条只保留目标文本，不要加入提示音、句号读法或明显的句尾语气。
- 裁掉过长的头尾静音，但保留少量自然边界，避免拼接后吞音或爆音。
- “十、百、千、万、亿”要录成可接在数字之后继续连读的中性语气。
- 批量生成后至少试听：`十`、`十一`、`二十`、`一百零一`、`一万零一十`、
  `一亿零一万`、`负二十三点五`，检查停顿、响度和声调是否一致。
